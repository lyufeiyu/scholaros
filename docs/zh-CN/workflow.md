# 分步研究与恢复

[English](../workflow.md) | **简体中文**

## 选择运行方式

研究说明最多支持 100,000 个字符，可填写背景、方法设想和约束。网页显示字符计数，超限粘贴会保留完整内容供修改。这个数值是输入上限；描述、其他资料和模型回答的总长度仍需符合所配置模型的上下文容量。

原来的自动流程仍是默认方式。想先检查中间结果，可以使用 `scholaros run "你的研究问题" --guided`，在终端菜单选择 `g`，或在 Web 新建项目时开启引导模式。

引导模式在范围界定、证据综合、方法设计和初稿完成后暂停。外发检索计划另行确认。检查阶段输出后，可确认继续或重做该阶段。确认只记录你的操作，不代表系统已经验证其科学有效性。

终端向导中，`y` 确认、`r` 重做当前阶段、`q` 保存并返回菜单。暂停后可以关闭终端，之后用下列命令继续。Web 会在进度条上方展示待确认内容；初稿可在研究制品区预览。

## 继续、局部重做和从头运行

将 `PROJECT_ID` 替换为 ScholarOS 显示的项目编号。下面的命令按需分别执行。

| 操作 | CLI 命令 | 保留什么 |
|---|---|---|
| 查看状态和制品路径 | `scholaros show PROJECT_ID` | 全部内容 |
| 确认引导阶段 | `scholaros approve PROJECT_ID` | 已完成结果，推进到下一个确认点 |
| 确认外发检索词 | `scholaros confirm-search PROJECT_ID` | 范围和已确认的检索计划 |
| 重试中断阶段 | `scholaros resume PROJECT_ID` | 已完成的上游阶段 |
| 从方法设计重做 | `scholaros rerun PROJECT_ID --from-stage designing` | 范围、论文清单和证据 |
| 从初稿重做 | `scholaros rerun PROJECT_ID --from-stage drafting` | 范围、论文清单、证据和方法设计 |
| 从头重做 | `scholaros rerun PROJECT_ID --from-stage scoping` | 上传资料和历史快照 |
| 列出旧版本 | `scholaros history PROJECT_ID` | 只读操作 |

阶段名包括 `scoping`、`searching`、`synthesizing`、`designing`、`drafting`、`reviewing`、`revising`。不能跳过缺失的上游结果或尚未完成的人工确认。局部重做会使下游结果和确认记录失效，上游成果不变。失败阶段可能重新调用模型；恢复粒度是阶段，而不是生成中的 token。

终审仍有问题时，`resume` 不会悄悄从头生成新稿。请先看检查结果，再选择需要重做的阶段。运行中的项目持有锁，会拒绝并发启动。进程退出释放锁后，`resume` 可以恢复遗留的“运行中”状态；仅重启服务器不会自动继续任务。

添加新参考资料或改变资料角色会回到范围界定，因为研究背景可能变化。在证据综合之后补充结果资料，会使证据综合及其后续阶段失效，但保留范围和检索结果。上传后从页面提示的阶段继续即可。

## 历史快照

显式重做、从头运行、拒绝检索计划，或给已完成范围界定的项目更改资料前，系统保存当前状态和生成制品：

```text
.scholaros/artifacts/PROJECT_ID/history/REVISION_ID/
```

`manifest.json` 记录原因、时间、项目状态和已复制制品的 SHA-256。提取后的 source 文本仍在项目制品目录；快照不重复复制这些文本，也不保留原始上传文件。快照失败时不会开始清理旧制品。生成文件通过原子替换写入，避免留下半份草稿。

在 Web 的“局部重做与历史版本”中可以查看、下载旧版本。目前没有一键回滚和自动保留数量限制，多次重做会增加磁盘占用。删除项目也会永久删除其历史。这不是独立备份；快照可能含私人研究资料，未经检查不要提交或分享。

## API 与兼容性

`POST /api/projects` 新增 `guided: true`；不传时保持原行为。操作接口为 `POST /api/projects/{id}/resume`、`/approve`、`/rerun?stage=designing`。历史接口为 `GET /api/projects/{id}/history` 和 `/history/{revision}/{name}`。原来的 `/run?restart=true` 保留，现在会先保存旧版本。

新字段存放在现有项目 JSON 中，不需要数据库迁移。缺少这些字段的旧项目仍按自动流程处理。新建的显式离线项目在重新打开、继续和重做时保持离线，包括从 Web API 操作。较早的离线项目未记录这一标记，不能自动推断，请重新创建离线演示项目。

当前实现是本地、阶段级流程，尚不包括执行中对话修改、逐章生成、历史一键回滚、持久化后台队列或多人审批权限。模型和外部检索服务仍可能出错；这些控制用于保留进度，不保证任务完成或科研质量。
