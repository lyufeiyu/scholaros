Public ScholarOS documentation should describe stable interfaces, usage boundaries, and public product positioning. Do not commit internal implementation history, internal project names, debugging records, user data, or secrets. Before publishing, confirm that `.env` is ignored and that no real key appears in documentation.

External-service terms, model names, API limits, and open-access policies can change. Permission decisions must follow each service's current official terms and each paper's license.

All generated content is working material for researcher review and revision. Public descriptions must not present ScholarOS as an autonomous author, ghostwriting tool, or guarantee of research quality.
