# 计算实验工作台

研究项目可在「实验」页运行团队提供的计算代码。主指标的“越大越好 / 越小越好”**只决定结果判优方向**，不修改上传的代码。实验独立于论文阶段；团队确认完整报告后，才会将其加入稿件资料。

## 选择代码

- **项目文件夹（默认）：** 在浏览器中选择整个文件夹，可包含子目录。上传后指定一个 Python 主文件；如需与基线比较，可选另一份基线主文件并填写它的运行命令；数据文件可选，脚本也可自行读取目录中其他文件。文件数量不限，合计不超过 2 GiB；隐藏文件不会上传。请勿把密钥放入项目目录。运行会绑定这次上传的文件夹版本；其他人更新目录后，旧页面须刷新并重新确认。
- **单文件兼容入口：** 仍可分别上传 CSV 数据集、基线 Python 脚本和候选 Python 脚本。

主文件选定后，会填入 `python 主文件.py`。可以填写已有终端命令作为参考，点击“获取命令建议”；**只有勾选允许发送代码**时，才会把主文件片段（最多约 12,000 字符）、README 片段（最多约 4,000 字符）、目录清单和参考命令交给当前配置的模型。未配置模型或未勾选时只返回默认命令。无论命令由谁提供，都必须检查后手动确认；系统仅接受 `python 选定主文件.py [参数]` 或对应的 `python -m 包.模块 [参数]`，不执行 Shell、安装依赖或运行其他入口。复杂的环境变量赋值与流水线暂不支持。

## 算法优化模式

项目文件夹模式下可以打开算法优化。主文件仍用于运行，不要求被修改；默认把目录中的现有 Python 文件都纳入候选范围，也可以手动取消不相关文件。模型会根据调用关系和研究目标判断实际需要修改的文件，返回各文件的完整候选代码和逐文件差异。算法文件不设数量上限，但单文件不超过 32 KiB、所选代码合计不超过 256 KiB；模型不能新建、删除文件或自动安装依赖。团队应先检查差异，再确认运行；原始上传目录保持不变。

运行时分别冻结原版目录和改进版目录。原版与候选版对每一组相同参数、相同随机种子使用同一命令和数据，报告保留文件哈希、每次试验和对应基线的指标差值。**负向结果、失败和无提升都如实记录**，模型提案或一次指标提升不等于算法有效性得到证实。

## 运行与记录

1. 填写研究假设、候选方案相对基线的变化、主指标及判优方向；默认使用 3 个随机种子、1 组空参数和每次 60 秒上限。高级选项可改为 1–3 个种子、1–4 组参数及每次 10–300 秒上限。
2. 确认运行命令、输入材料与权限，启动受限容器。项目文件夹只读挂载在 `/input`；脚本可读取 `SCHOLAROS_SEED`、`SCHOLAROS_PARAMS`（JSON）以及可选的 `SCHOLAROS_DATASET`。将结果直接写入 `SCHOLAROS_OUTPUT` 指向的 `/tmp/result.json`，格式为 `{"metrics":{"accuracy":0.5}}`。示例数值仅说明格式，并非真实实验结果。
3. 页面保存输入哈希、镜像标识、每次试验状态和结果。有基线时按相同种子比较；无基线时只列候选参数组。主指标由脚本计算，平台不证明方法公平，也不把失败运行当作成果。只有完整报告可由团队确认后导入项目；导入会使受影响的旧稿件待更新。

运行使用本机已有的 Docker `python:3.11-slim` 镜像（仅 Python 标准库）。ScholarOS 不自动下载镜像，也不会在没有 Docker 时退回宿主机执行；暂不支持额外 Python 依赖、GPU、远程执行或多用户并发写入。容器禁网、根文件系统只读，只给结果文件写入权限并限制资源；这不是对恶意代码的完整安全保证。

## 本机独立运行

「本机运行」不要求选择论文项目。上传代码目录、填写执行命令、指定指标文件相对路径（CSV 或 TXT，可写 `../outputs/运行名/任务/metrics.csv` 读取运行目录中代码文件夹外的输出）和要统计的指标列名或键（留空则提取全部数值列 / 键），确认宿主机执行风险后开始。命令的工作目录固定为上传目录；stdout 与 stderr 合并滚动写入日志，页面最多展示尾部内容。运行中及结束后，系统按指标文件抽取指定列 / 键的样本数、均值、最小值、最大值和最新值，形成统计表。也可以给出参考命令后让模型识别再手动修改。

上传完成后，运行工作台左侧展示上传时的代码目录，点击文件可只读预览（单文件最多 128 KiB）；右侧展示历史记录、操作提示、指标表和滚动终端输出。指标文件解析上限为 5 MiB，终端日志最多保存 2 MiB；超出限制会显示明确提示，不会无限读取。运行接口仅接受本机访问，不接受跨站写操作。

运行记录与论文项目分离，保存在 ScholarOS 数据目录的 `runs/` 下，之后可查看历史。由于这是有意在宿主机执行，平台不提供容器隔离，也不会把它当作实验页的受限运行；请只运行已经确认的代码。进程可以读写本机用户有权限的其他目录，以上限制不是对恶意代码的安全隔离。服务在任务运行时意外退出，原始子进程可能仍在运行，需要在本机检查并手动结束。

### 从 README 到研究项目

选择本机运行记录后，勾选允许发送 README.md，再让模型分析研究对象、技术方案与实验说明，形成**详细的研究想法或核心问题**（含技术流程、数据依赖、对照、指标及待核实边界）。研究者可以直接修改这段文字，再带入研究工作台的创建表单。项目可默认选择英文期刊与 IEEEtran，但仍须由研究者检查配置与材料后创建，并在项目页启动原有的分阶段流程；本机运行不会绕过检索、方法设计、审阅和人工确认直接生成论文。分析会先在上传目录中查找一个大小写不敏感的 `README.md`，只把这个文件按行号分批交给模型；目录中的 Python、脚本、配置和数据文件都不会读取或发送。没有 README.md 时会直接提示重新上传包含该文件的目录。模型依据 README 中明确的研究对象、技术方案、实验说明和限制，结合范围界定与方法设计要求形成详细研究说明。原始数据不会因转项目而自动作为论文结果。

研究项目形成完成稿后，下方按章节展示正文。研究者选择任意顶级章节、提交定向修改要求、核对模型给出的候选正文，确认后才替换该章节；其他章节不重写。系统保留原稿历史，重建 LaTeX 与质量检查，并作废旧交付包。表格继续按 IEEE 双栏通栏设计，未证实的比较结果留待补充。具体投稿、作者、引文与实验结论始终由研究者核对。
