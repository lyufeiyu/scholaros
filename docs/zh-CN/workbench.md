# 项目工作台与交付

[English](../workbench.md) | **简体中文**

ScholarOS 按阶段呈现当前项目工作区，同时保留可恢复的七阶段执行游标并兼容旧项目。左侧栏只负责项目级导航；阶段切换、修改和结果都集中在“当前研究项目”页面内部。

## 配置任务

可选择六类工作：由材料形成论文、重写已有稿件、科研诚信与证据核查、独立审阅、按意见返修、适配新目标。配置还记录使用场景和目标名称、输出语言、研究分析边界、作者表达、学习集篇数、参考文献目标、机制图策略和交付范围。Markdown 与 LaTeX 固定同时保留。

配置保存在项目 JSON 中，旧项目无需数据库迁移即可获得保守默认值。字段变化只从最早受影响阶段开始失效，旧版生成内容会先进入历史快照。只改变交付格式时会立即撤销旧导出，避免把过期稿包继续展示为当前版本。

“只使用已有材料与结果”会完全跳过第三方论文检索；如果项目中没有任何本地资料或结果，工作流会停止并提示补充材料，不会静默改回联网模式。

命令行示例：

```bash
scholaros run "你的研究问题" \
  --workflow transfer --scene conference --target-name DemoConf \
  --language zh --research-mode materials_only \
  --same-field-papers 5 --target-venue-papers 5 \
  --reference-count 30 --format md --format tex
```

## 分阶段修改并确认

每个阶段都可先保存修改草稿；保存不会改变现有结果，确认后才会保存历史快照、使本阶段及下游结果失效并重新运行。范围阶段直接显示一份研究贡献方案，包括研究问题、核心贡献、注意边界和论证框架，不再要求从三个相近选项中选择。证据阶段显示学习计划、论文清单、证据账本三个文件，以及每份本地材料和每条证据记录。方法阶段即使没有最终图片，也会给出图与表的用途、构成、字段、数据要求、图注和表达边界。

## 在同一项目检查与修订

稿件阶段同时显示 Markdown 与 LaTeX 原文本；LaTeX 导出使用仓库本地保存的 IEEEtran 期刊模板，但投稿时仍应以目标期刊最新作者指南为准。方法与图表阶段会把流程图以 Mermaid 预览、把表格规划以可读表格呈现；加载或解析失败时仍保留文字说明。质量阶段逐项显示严重程度、检查出的问题和建议修改点。修订统一使用阶段顶部的“保存修改草稿—确认并更新后续”机制，不再额外设置一套“意见与同任务返修”表单。最后阶段将交付与项目材料总览并排呈现，统一核对范围、材料、证据、图表、稿件和质量状态。

## 准备交付

可通过 API 或命令行执行：

```bash
scholaros delivery PROJECT_ID
```

交付阶段保留 `paper.md` 并生成 `paper.tex`，再写出 `delivery-manifest.json` 与 `delivery-package.zip`。清单记录请求和可用格式、质量阻塞项、文件大小和 SHA-256、共享边界，以及“本地交付不等于投稿或发布”。“仅稿件”和“投稿材料包”只包含请求的稿件格式；“完整本地稿包”还包含证据、设计、图表规划和内部审阅记录，可能带有上传材料摘录，因此对外分享前必须人工检查。ZIP 不包含原始上传资料、密钥、数据库、历史版本和本机路径。项目页会显示版本时间线：每个完成阶段和最终完成稿都自动保存一份版本，点击任一版本即可用七阶段导航查看当时的状态和制品，返回当前版本后恢复最新内容。项目页可将 Markdown 以纸张样式预览并通过浏览器打印为 PDF，同时直接查看 LaTeX 原文本。

Markdown 和 TeX 是可编辑基础稿，不是已经套好目标期刊版式的终稿。研究者仍需补充最终媒体，回到原文核验证据，应用目标场景的最新模板，确认作者、伦理、基金等元数据，并亲自决定是否投稿。
